## 結論（先出し）

**`api-sg.tingot.com` は新規(2026-01-08登録)の中華圏インフラ系ドメインで、SOCRadar が `malware` ラベルでフラグ。VT 上でこのドメインと通信するサンプルとして `Nimnul/Wapomi/Banload` 系ファイル感染型ウイルス (検出最大 67/71、複数の正規Adobe/dotnet/MSバイナリへの感染検体) が紐づいており、悪性インフラとして扱うべき。** ただし malicious 判定は 1 ベンダーのみで、メイン dropper C2 は別ドメイン (`ddos.dnsnb8.net:799`)。本ドメインは補助テレメトリ／別キャンペーン共有C2／侵害された正規バックエンドAPIのいずれか。

**親 `tingot.com` 自体は DNS にAレコードなし (NXDOMAIN)、`www.tingot.com` も解決不能。** API/CDNサブ専用に設計された不可解な構成 = 一般公開Webサイトとしては異常。

リスク評価: **High (Suspicious-Malicious)** — 通信先として観測されたら隔離・調査推奨。

## 6. 解釈（仮説）

1. **メイン解釈 (高確度)**: `tingot.com` 系は中華圏 (HK/中国本土) のモバイルアプリまたは Web サービスのバックエンド (Cisco Umbrella top 10K に入る程度の利用者) 。`api-sg` は東南アジア向けAPIエンドポイント。何らかの形で Nimnul/Wapomi 検体がこのAPIをcallしているため、**侵害された正規サービス** または **マルウェアキャンペーンに利用される疑似サービス** の可能性。
2. **副解釈**: SOCRadar の自動IOC収集が他キャンペーンで観測された通信先として登録した可能性。誤検知の余地は残る (1/93)。
3. **追加証拠**: 親 `tingot.com` 自体はクリーンだが、TLS発行が **vTrus DV (中国系)**・レジストラが **HiChina (Alibaba)**・レジストラ表記が中国電話番号・ホスティングが Tencent Cloud という構成は、過去観測される **中華系 Pig-Butchering / 偽トレーディングアプリ / 不正カジノ系アプリ** のインフラパターンと一致する。フィッシングEMLとの紐付けはこの仮説を補強する。

## 9. 追加調査結果 (Docker起動後)

### 9.1 隔離ブラウザ実アクセス (malware-fetch)

`tools/malware-fetch/Quarantine/` に成果物保存。

| 対象 | 結果 | 詳細 |
|---|---|---|
| `https://www.tingot.com/` | **DNS解決失敗** | `ERR_NAME_NOT_RESOLVED` (隔離コンテナ内Playwrightで再現) |
| `https://tingot.com/` | **DNS解決失敗** | ホストOS / 隔離コンテナ両方でNXDOMAIN |
| `https://api-sg.tingot.com/` | 503 ✅成功 | レンダリングされたHTMLは `<title>503 Service Temporarily Unavailable</title><hr><center>stgw</center>` のみ (Tencent STGW デフォルトページ) |
| `https://static1.tingot.com/` | 403 | ホスト直接curlで Forbidden |
| `https://r1.tingot.com/`, `r1-eo.tingot.com` | 503 | 同じstgw |
| `https://r1-cf.tingot.com/` | DNS解決失敗 | NXDOMAIN |

**重要観測**: 親 `tingot.com` / `www.tingot.com` / `r1-cf.tingot.com` が **NXDOMAIN** ←→ `api-sg`, `static1`, `r1`, `r1-eo` のみが解決される。**通常のWebサービスは `www` か apex で応答する**ため、API/CDNサブのみ生かす構成は **モバイルアプリやデスクトップソフトのバックエンドAPI／C2／不正サービス専用** のシグナル。

### 9.2 Nimnulクラスタ補強

`api-sg.tingot.com` と通信するNimnul検体がドロップする他バイナリ全てが悪性ファミリ:

| SHA256 | M/71 | Suggested Label | 注記 |
|---|---|---|---|
| `4354970ccc7cd6bb...` | **67** | trojan.banload/jqjr (banload+wapomi) | 15.5KB Win32 (downloader) |
| `79dcb722b71b3d4b...` | 60 | virus.nimnul/wapomi | 124KB (apphost.exe を装う) |
| `c9b8c5253145778f...` | 60 | virus.nimnul/vjadtre | **signature_info=True** ← 正規バイナリ感染 |
| `c661e2acc46b40c5...` | 57 | virus.nimnul/vjadtre | **8.4MB / signature_info=True** ← `singlefilehost.exe` (Microsoft .NET) 感染 |

→ **Nimnul/Wapomi は file infector として正規 Microsoft .NET ランタイム / Adobe Acrobat バイナリに感染する** ことが本検体クラスタで確認された。デジタル署名が残ったままだが、ペイロード追加で末尾ハッシュ崩壊。

### 9.3 CNAME `ins-dytegdsp.ias.tencent-cloud.net` 単独調査

- VT検出: malicious=0
- `tencent-cloud.net` は 2012年登録の正規Tencent Cloudドメイン
- このinstance IDのCNAMEは **api-sg.tingot.com専用** に割り当てられたTencent IAS dynamic hostname (他キャンペーン共有なし)

### 9.4 外部脅威DB公開分への登録状況

- **ThreatFox / URLhaus / SOCRadar (公開部分) / OTX**: `tingot.com` 系 IOC 登録なし (WebSearch検索結果より)
- **ANY.RUN / Triage / Hybrid Analysis (公開)**: `api-sg.tingot.com` を含むサンドボックス分析記録なし
- → SOCRadar の `malware` 判定は **同社プライベートIOCフィード由来** (VT経由のみで参照可能)
